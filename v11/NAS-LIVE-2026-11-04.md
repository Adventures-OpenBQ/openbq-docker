# v11 on main and the NAS — November 4, 2026

V11 is running on the NAS alongside the retained legacy deployment. The public
BDOBB and openbq-docker repositories now use `main` as their default branch.
TemporalDB's `main` is updated in its **private** repository. Its packaged
Business Source License 1.1 matches the repository's LICENSE. No repository
visibility was changed.

TemporalDB remains an optional, separately licensed service. BDOBB's normal
provider widgets, tables, charts and Rita use their configured services without
requiring it. Retained queries, temporal selection, saved-policy acquisition and
protected replay require that integration.

## Roll back the v11 entry points

On the NAS, using the existing authorized SSH account:

```sh
sh /share/Container/openbq-v11-staging/cutovers/20261104-v11-main/rollback.sh
```

The tested script restores the exact prior persisted Serve configuration,
verifies that the managed Tailscale configuration removed the three new routes,
and stops only the live gateway/table/MCP services. Original HTTPS routes and
the legacy database remain working. It deletes no container, image, volume,
archive or data. New v11 data remains in its separate stores; this operation
does not downgrade migration 044 or overwrite a database with a backup.

The restore guard refuses to overwrite unrelated Serve edits made after this
cutover. If that guard reports a conflict, inspect those edits before applying
the stored configuration. The first rehearsal exposed a redundant imperative
`serve off` command racing with the managed-file watcher; the corrected script
uses and verifies that watcher instead. The actual corrected rehearsal passed.

To bring v11 back after this rollback, use the private Compose configuration
with `up -d`, then the saved `publish.sh`; its endpoint publication is separate
from database recovery. Keep the retained ten-example recovery procedure for
disaster recovery into new volumes. Do not restore snapshots over live stores.
