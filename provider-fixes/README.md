# Provider compatibility overlay

Reviewed sources from OpenBQ PRs [7746](https://github.com/openbq-org/OpenBB/pull/7746) and [7747](https://github.com/openbq-org/OpenBB/pull/7747), commits `2462711` and `c2c8b60`. The application script verifies package versions and every original source hash before copying any file. It fails closed on upstream drift. Remove this overlay when published provider versions include the fixes. No credentials are required for applying it.

`openbb_core/app/command_runner.py` is a local fix with no upstream PR yet. Commands do CPU-bound work (pandas strategy pricing, curve bootstraps over whole DTCC day slices) in sync and async code, and on the server's single event loop one such command froze every route, `/widgets.json` included. The overlay runs each provider's commands on that provider's own persistent event loop in its own thread, and runs CBOE and CFTC commands one at a time. `openbb_finra/models/bond_list.py` and `openbb_federal_reserve/models/institution_structure.py` change only default parameters, FINRA bonds to Treasuries and FFIEC institution structure to transformations, because the upstream defaults built 150–160 MB responses. `openbb_core/api/router/commands.py` lets the app start with `OPENBB_API_AUTH=true`: openbb-core 2.0.1 rebuilt a shared endpoint's signature per route (duplicate `__authenticated_user_settings`) and placed that parameter after keyword-only ones. `openbb_cftc/utils/fx_valuation.py` prices each FX print from its peers without re-extracting the whole pair per print: upstream's leave-one-out curve made a forex swap_trades call quadratic (over an hour of CPU on a 43k-trade day); results are unchanged.

A command now gets a deadline on its provider's loop: 55 seconds, 90 for CFTC, set by `OPENBQ_COMMAND_TIMEOUT` or `OPENBQ_COMMAND_TIMEOUT_<PROVIDER>`. Past it the command is cancelled at its next await, which frees the provider's lock, and the request gets a 504 instead of hanging. `openbb_core/api/exception_handlers.py` read `error.errors` without calling it, so a provider input missing from the request returned 500 instead of 422; it also maps `TimeoutError` to 504 and a non-JSON upstream body to 502, each with a clear message. `openbb_core/app/provider_interface.py` keeps a provider-only required input optional on the shared route but marks that provider's widget input `optional: false`, so the client asks for it instead of sending null.
